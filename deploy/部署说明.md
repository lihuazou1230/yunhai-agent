# 部署说明 · Agent 后端（IIS 同源子应用 `/yhai`）

> 目标：让 **`http://124.220.159.58/workspace/` 这个部署页也能用 AI 助手**。
> 一句话结论：agent 跑在服务器上，由 IIS 用 **80 端口**反代成同源子路径 `/yhai` ——
> 不开新端口、不动安全组、不需要 CORS 配置。

---

## 一、为什么不能"继续用本机 agent"

部署页里 AI 助手页的基地址原本默认是 `http://127.0.0.1:8000` —— 那是**访问者自己的电脑**。
就算访问者就是你、agent 也正好在这台机器上跑着，浏览器还有第二道门：

> Chrome 142 起推行 **Local Network Access**：公网页面访问回环/内网地址（`127.0.0.1`、`192.168.x.x`）
> 需要用户授权，而**只有安全上下文（HTTPS）才有资格申请这个权限**。
> 部署页是 `http://124.220.159.58`（非安全上下文），连弹授权的机会都没有。
> 出处：[Chrome 开发者博客 · 區域網路存取權的新權限提示](https://developer.chrome.google.cn/blog/local-network-access?hl=zh-tw)

所以现状是：**HTTP 部署页 + 本机回环 agent = 必然连不上**。

改 CORS 只解决第一道门（顺手也做了：`CORS_ORIGINS` 里已加 `http://124.220.159.58`，
万一以后改成"另开端口直连"还能用）。

## 二、方案长什么样

```
浏览器  http://124.220.159.58/workspace/          ← 前端（静态，第八阶段那份）
          AI 助手页基地址 = http://124.220.159.58/yhai
              │  同源请求（不跨域 → 不需要 CORS；桌面壳 CSP 的 connect-src 'self' 也满足）
              ▼
IIS（80 端口，主站 Default Web Site）
  └── 子应用 /yhai  →  URL Rewrite + ARR 反代  →  http://127.0.0.1:8000
                                                    uvicorn（计划任务常驻，只监听回环）
```

### 为什么是 ARR，而不是 HttpPlatformHandler

**HttpPlatformHandler v1.2 自带 8KB 输出缓冲，且官方从未修、无法配置关闭。**
拿它扛 SSE 的结果就是"回答憋到最后一次性吐"——而逐字吐是本服务最不能丢的特性。

- [aspnet/IISIntegration#7](https://github.com/aspnet/IISIntegration/issues/7)：ASP.NET 团队实测 *"the buffer is 8kb"*，修复只进了 AspNetCoreModule v0.8，HPH v1.3 从未发布
- [Lex Li（IIS MVP）](https://docs.lextudio.com/blog/httpplatformhandler-v2/)：*"v1.2 has a 8-KB output cache that we cannot disable"*
- 在 handler 上加 `responseBufferLimit="0"` 只关掉 IIS 那层 4MB 缓冲（官方默认 4194304 字节），**关不掉模块内部那 8KB**
- ARR 的响应缓冲是**可配置**的：机器级 `minResponseBuffer=0` 之后 chunked/flush 正常透传（[微软官方博客](https://learn.microsoft.com/en-us/archive/blogs/asiatech/transfer-encoding-chunked-is-not-in-the-response-header-when-using-arr)）

ARR 的代价是**它不管进程**，所以额外用计划任务把 uvicorn 常驻起来（脚本已自动配好）。
（另一条路是 LeXtudio 的 HTTP Bridge Module，schema 与 HPH 兼容且修了 SSE；想少一个进程可以以后试。）

### 目录约定（刻意分开）

| 路径 | 放什么 | 为什么 |
| --- | --- | --- |
| `C:\yunhai-agent\` | 应用 + `.venv` + `data\` + `.env` + `logs\`（**不在网站目录下**） | `.env` 里有 API Key，放网站目录里就有被静态处理器读走的风险 |
| `C:\inetpub\wwwroot\yhai\` | 只有 `web.config` | 子应用物理目录越空越安全；web.config 里只有一条反代规则 |

## 三、前置条件

| 项 | 说明 |
| --- | --- |
| 访问方式 | RDP 登录 `124.220.159.58`（22/SSH 关着，3389 开着） |
| 权限 | **管理员**（要装 IIS 模块、建子应用、注册计划任务） |
| 外网 | 服务器要能出去：下载 Python / IIS 模块、调 DeepSeek 与 SiliconFlow |
| 两个 Key | ① DeepSeek（生成侧）② **SiliconFlow**（向量侧 bge-m3，申请：<https://cloud.siliconflow.cn/>） |
| 系统 | Windows Server 2012 R2 + IIS 8.5 + PowerShell 4.0（脚本按这个环境写） |

**Python 只能是 3.10 ~ 3.12**：3.13 起官方最低要求 Windows 10，这台机器装了也跑不起来。
**3.12 是最后支持 Server 2012 R2 的版本**（官方文档原文：*Python 3.12 supports Windows 8.1 and newer*）。
脚本默认下载 3.12.10 并装到 `C:\Python312`；若安装报错，多半是缺 **UCRT**：
装 VC++ 2015-2022 Redist（x64）或打 KB2999226 / KB3118401 后重跑。

**为什么不装 torch**：`sentence-transformers` 会拖 torch（装完约 2GB），torch 官方只支持 Win10+，
这台服务器大概率装不上。所以服务器形态用 `EMBEDDER=api`（SiliconFlow 的 `BAAI/bge-m3`，走 HTTPS）。

> **换了向量模型 = 换了向量维度**：本机 `bge-small-zh` 是 512 维，`bge-m3` 是 1024 维，
> 所以**本机 `data\` 不能拷过来复用**。服务器上干净起步，重新上传文档即可
> （本机样本在 `yunhai-agent\eval\docs\`：常见问题.jsonl、云海工作台使用手册.md、RAG技术笔记.md）。

## 四、操作步骤

### 第 1 步：本机打 Agent 部署包

```powershell
cd C:\Users\asus\Desktop\个人项目\yunhai-agent
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\build-agent-package.ps1
# 产出：yunhai-agent\agent-deploy-package.zip（约 100 KB，不含任何模型与二进制）
```

### 第 2 步：RDP 上去装

1. 把 `agent-deploy-package.zip` 粘进远程会话（RDP 支持直接复制粘贴文件），解压到桌面之类的位置。
2. **右键 `install.ps1` →「使用 PowerShell 运行」**（必须管理员，否则脚本直接拒绝）。
3. 脚本依次做八步：环境侦察 → 准备 Python → 部署应用+venv → 写 `.env` → 离线自检 →
   装 URL Rewrite + ARR 并开机器级代理 → 建子应用 `/yhai` → 注册常驻任务 →
   经 IIS 探活。中途会让你粘贴两个 Key。
4. 看到「部署完成」后按屏幕提示在浏览器里复核。

> 服务器出不了外网时：把 `python-3.12.10-amd64.exe`、`rewrite_amd64_en-US.msi`、
> `requestRouter_amd64.msi` 和 `install.ps1` 放同一目录，脚本会优先用包内的离线文件。

### 第 3 步：重新打前端包（让部署页默认就连对地址）

前端新增了构建期变量 `VITE_AGENT_ENDPOINT`，打包脚本已把默认值指到 `/yhai`：

```powershell
cd C:\Users\asus\Desktop\个人项目\yunhai-workspace
pnpm deploy:package        # 内部设 VITE_AGENT_ENDPOINT=http://124.220.159.58/yhai
# 然后把 deploy-package.zip 拖进 RDP，右键 install.ps1 运行（第八阶段那套流程）
```

装完后打开 `http://124.220.159.58/workspace/` → AI 助手页应当**默认**就填着
`http://124.220.159.58/yhai`，点「检测」直接变已连接。

> 不想重打前端包也行：在 AI 助手页侧栏把基地址手填成 `http://124.220.159.58/yhai`
> （值存在各自浏览器本地）。但换设备/换浏览器就得再填一次，所以推荐重打。

### install.ps1 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-AppName` | `yhai` | 子应用名（= URL 路径段）；改了要同步前端基地址 |

| `-EmbedApiKey` / `-EmbedApiBaseUrl` / `-EmbedApiModel` | 交互询问 / SiliconFlow | 向量侧 |
| `-SkipArrInstall` | 关 | 跳过 URL Rewrite / ARR 的检测与安装 |
| `-SkipSelfCheck` | 关 | 跳过第 4 步离线自检 |
| `-Force` | 关 | 重建 venv、重写 `.env` |
| `-NoPause` | 关 | 跑完不等按键（自动化调用） |

一次给全 Key 的例子：

```powershell
.\install.ps1 -LlmApiKey "sk-xxx" -EmbedApiKey "sk-yyy"
```

### 服务器上 `.env`（`C:\yunhai-agent\.env`）

由 install.ps1 生成，UTF-8 **无 BOM**。关键行：

```ini
EMBEDDER=api
EMBED_API_KEY=sk-...        # SiliconFlow
AGENT_URL_PREFIX=/yhai      # 双保险：ARR 已剥前缀，这里是为了以后换托管方式也不炸
```

> ⚠️ 环境变量名必须是 `AGENT_URL_PREFIX`（pydantic-settings 按**字段名**推环境变量名，
> 写成 `URL_PREFIX` 会静默失效）。改完 `.env` 要重启后端（见第八节）。

### ARR 的机器级设置（脚本用 appcmd 写 `applicationHost.config`）

```bat
%windir%\system32\inetsrv\appcmd.exe set config -section:system.webServer/proxy /enabled:"True" /commit:apphost
%windir%\system32\inetsrv\appcmd.exe set config -section:system.webServer/proxy /minResponseBuffer:"0" /commit:apphost
```

- `enabled` 与 `minResponseBuffer`（SSE 关键，默认 256KB）有官方出处；
  `timeout` / `preserveHostHeader` 的属性名**未取得公开 schema 原文**，脚本是尽力而为地设置（失败只警告）。
  对不上就手工来：IIS 管理器 → 服务器节点 → **Application Request Routing Cache** →
  **Server Proxy Settings** → 勾 Enable proxy、Response buffer threshold (KB) 填 0、
  Time-out (seconds) 填 1800 → Apply。
- **这些设置只能写 `applicationHost.config`**：`system.webServer/proxy` 是机器范围的节，
  写进 `web.config` 会直接 **500.19 / HRESULT 0x80070021（配置节被锁定）**。

## 七、排障

**先看两处日志**：

```powershell
Get-Content 'C:\yunhai-agent\logs\agent.log' -Tail 50      # 后端启动报错 / traceback
Get-Content 'C:\inetpub\logs\LogFiles\W3SVC1\*.log' -Tail 20   # IIS 侧访问日志（可选）
```

本机绕过 IIS 直测后端（区分"后端问题"还是"IIS 问题"）：

```powershell
Invoke-WebRequest http://127.0.0.1:8000/api/health -UseBasicParsing | Select-Object -Expand Content
```

| 现象 | 原因与修法 |
| --- | --- |
| **500.19 + 0x8007000d**（"无法读取配置"） | 配置里出现了**未安装模块**的节：例如 ARR/URL Rewrite 没装就写 `<rewrite>`。装模块后 `iisreset` |
| **500.19 + 0x80070021**（"配置节被锁定"） | 把机器级节写进了 `web.config`（最常见是 `system.webServer/proxy`）→ 挪到 appcmd/管理器里设 |
| **500.19 + 0x800700c1** | 模块位数与应用池不匹配：装了 x86 的模块却用 64 位池（或反之） |
| **500.21**（"模块无法识别"） | handler 引用了未注册的模块 → URL Rewrite / ARR 没装好 |
| **502.3**（"Bad Gateway"） | ARR 连不上后端：uvicorn 没在跑 / 端口不对 / 防火墙本机策略。先直测 `127.0.0.1:8000/api/health` |
| **502.5** | ARR 场景多为 WebSocket 相关；若换成 HPH 则是进程启动失败 |
| **404.13**（请求体太大） | 上传超限：确认 `/yhai` 的 `requestLimits maxAllowedContentLength`（本包给到 200MB） |
| **回答憋到最后一次性吐** | ARR 缓冲没关：`minResponseBuffer=0` 没生效（见第六节手工路径）；同时确认没有别的动态压缩在起作用 |
| **回答中途被截断** | ARR 代理超时（默认 120 秒）：把 `timeout` 调大（脚本尝试设成 30 分钟） |
| **400.605 Maximum number of forwards (ARR)** | 规则自循环。本规则目标是 `127.0.0.1:8000`，正常不会；检查是否又把 `/yhai` 指回了本站 |
| **404（api 全 404）** | 反代规则没生效：子应用 `/yhai` 的 `web.config` 里 `<rewrite>` 在不在；URL Rewrite 装了没 |
| **一停任务端口还占着**："address already in use" | 结束计划任务有时只结束 cmd 包装进程。脚本重启时会兜底清掉带本应用目录的 python；手工同理：`Get-WmiObject Win32_Process -Filter "Name='python.exe'"` 后按命令行筛选杀 |
| **问什么都拒答** | 库里没文档（服务器干净起步，先传文档）；或 `EMBED_API_KEY` 无效 —— 用 `/yhai/api/health/embedder` 验证（它会真编码一次） |
| **报「Embedding dimension mismatch」** | 把本机 `data\` 拷过来了（512 维 vs 1024 维）。删掉 `C:\yunhai-agent\data\` 重启，重新上传 |
| **报「未配置 LLM Key」** | `.env` 的 `LLM_API_KEY` 空着，或 `.env` 被写成了带 BOM（用「UTF-8 无 BOM」保存） |
| **首次提问特别慢** | 正常：首次调用向量 API。之后有进程常驻就不会了 |
| **页面报「连不上 Agent 后端」** | 先确认基地址是 `http://124.220.159.58/yhai`，再直接浏览器打开 `/yhai/api/health` 看有没有 JSON。两者都好而页面不通 → 看浏览器控制台（CORS / 混合内容） |

## 九、已知取舍

- **接口没有鉴权**：谁猜到 `/yhai/api/*` 谁就能用（花你的 DeepSeek 额度、往库里传文档）。
  当前是"靠路径不公开"苟着。收紧有两条路：IIS 侧对 `/yhai` 限来源 IP，或加共享 token（需前后端各改一点）。
- **向量化依赖外部 API**：SiliconFlow 挂了就入库/检索失败（生成侧同理依赖 DeepSeek）。
  这是"不在 2012 R2 上装 torch"换来的代价，是刻意的。
- **`/yhai` 与前端不同源时**需要补 `CORS_ORIGINS`（同源部署下不需要）。
- **`preserveHostHeader` 默认 false**：后端看到的 Host 是 `127.0.0.1:8000`。
  本服务没有 Host 校验（无 `TrustedHostMiddleware`），所以不受影响。

## 十、上线前还要现场确认的几件事

调研里明确标了"未取得公开出处/需实测"的点，第一次部署时请顺手验一下：

1. **SSE 端到端**（最重要）：用第五节的 `curl -N` 走 80 端口，确认事件是陆续出现的。
2. **10MB 上传端到端**：大文件入库走的是异步任务，经 IIS 与 ARR 的请求体缓冲要实测（关注 404.13）。
3. **ARR `timeout` / `preserveHostHeader` 的确切属性名**：在服务器上 `%windir%\system32\inetsrv\config\schema\`
   下找 ARR 的 schema 文件，或 IIS 管理器界面核对后再固化成脚本参数。
4. **若改用 HttpPlatformHandler / HTTP Bridge**：HPH 不剥 `/yhai` 前缀（未证实，但风险高），
   而 `.env` 里已经写了 `AGENT_URL_PREFIX=/yhai` 兜住这一点；HTTP Bridge 修了 8KB 缓冲，可作 ARR 之外的备选。
