# RAG 技术笔记（评测用知识库样本）

> 第十阶段的实现笔记。阈值、参数、选型结论都写在这里，方便直接问「为什么是 0.4」。

## 1. 文档管道

解析按扩展名分流：PDF 用 pypdf 逐页抽文本，Markdown 与纯文本整篇进入分块器，
JSONL 一行一条天然成块。上传类型白名单是 pdf、md、txt、jsonl 四种，
单文件上限 10MB，超过 2MB 的文件转后台异步入库并先返回任务 ID。

分块用递归字符切分，默认块长 500 个字符、重叠 80 个字符。
分隔符按「空行 → 换行 → 中文句末标点 → 逗号 → 空格 → 单字」逐级降级，
中文句末标点是必须的，否则一整段中文会被当成一个词硬切。

## 2. 幂等入库

文档 ID 取文件内容的 SHA-256 前 16 位。内容没变就直接跳过，一块向量都不会新增；
同名来源重新上传时先按来源清掉旧向量再写新的，因此不会出现新旧两份并存。
每条向量的 ID 是「文档 ID:块序号」，重复入库只会覆盖同一批 ID。

## 3. 向量化选型

默认模型是 bge-small-zh-v1.5，输出 512 维向量，做了 L2 归一化，存储用余弦距离。
查询侧要加指令前缀「为这个句子生成表示以用于检索相关文章：」，文档侧不加。
零依赖兜底方案是字符 bigram 哈希向量，没有语义能力但完全确定，用来跑单元测试。
不想在本机装 torch 时，也可以切到 OpenAI 兼容的 /embeddings 接口，例如 bge-m3。

## 4. 检索与阈值

默认检索 top-k 为 4。语义检索的分数是余弦相似度，有绝对量纲，阈值校准结果是 0.4。
字面方案用 BM25，参数 k1 取 1.5、b 取 0.75，中文按单字加相邻双字入索引。
BM25 的原始分用固定尺度压缩成 `raw / (raw + 8)`：**不能**按本次查询的最高分归一化，
那样每条查询的第一名恒为 1.0，阈值就形同虚设（第一版评测里正是这么暴露出来的）。
压缩之后它仍然与余弦不是同一量纲，因此需要一条**独立**的阈值（0.6）。
命中分数低于阈值就当作「知识库里没有」，不进生成环节。

## 5. 生成侧约束

系统提示写死了三条规矩：只依据上下文回答、上下文不足就明说不足、结论要能指到出处。
引用块由后端按检索结果生成，不依赖模型自报编号，避免模型编造来源。
兜底三模式：A 拒答（默认，不消耗额度）、B 裸答并在回答开头标注「不基于知识库」、C 联网搜索（后置）。
知识库未命中时，模式 A 会直接返回固定文案「知识库里没有检索到与该问题相关的内容」。

## 6. 接口与流式协议

接口一共四组：文档上传与列表、流式问答、会话历史、健康检查。
所有产生内容的接口都走同一条 SSE 事件流，事件类型有 token、tool_call、tool_result、
citation、proposal、done、error 七种。前端因此只需要写一套 ReadableStream 解析逻辑。
流式响应必须带 `X-Accel-Buffering: no`，否则反向代理会把输出攒成一坨再发，逐字效果会消失。

## 7. 评测方法

评测集分两半：库内问题带期望来源文件，库外问题不带。
指标用 recall@1、recall@k 与 MRR；阈值扫描同时看「库内保留率」和「库外拦截率」。
库外问题里特意混入「同领域但库里没有」的题目（例如问 bge-large 的维度），
这类题天然会拿到中等偏高的相似度，单靠阈值拦不住，必须靠生成侧的拒答约束兜底。
